# API contracts

## Registration service (TICKET-0104)

There is no registration HTTP endpoint yet. `UserService.register(RegistrationRequest)`
is the Java application-service boundary. Existing HTTP access policy remains in
[security](security.md); HTTP Problem Details mapping belongs to TICKET-0107.

| Input | Contract |
| --- | --- |
| email | Required valid email, stripped and lowercased with `Locale.ROOT`, at most 254 characters after normalization |
| password | Required nonblank string, 12–128 Java characters, preserved exactly (including surrounding spaces) |

Validation executes inside the service even for non-HTTP callers. Input has no role,
enabled flag, hash, or token fields. Only EMPLOYEE may be assigned by registration.
`RegisteredUser` returns UUID `id`, canonical `email`, `enabled`, and an immutable
set of role names. It contains no JPA entity, password, hash, or token.

`RegistrationException.getReason()` returns `INVALID_INPUT`, `EMAIL_UNAVAILABLE`,
`ROLE_UNAVAILABLE`, or `PERSISTENCE_FAILURE`. Messages are fixed and omit submitted
values; persistence failures do not retain a database cause. Missing reference
roles and failed writes leave no partially registered user. Duplicate canonical
emails, including concurrent attempts, yield `EMAIL_UNAVAILABLE`.

Registration processes one identity per call; there are no list/query endpoints
or pagination changes in this ticket. Future HTTP mapping must consider email
existence disclosure and must not serialize internal validation violations.

## OAuth 2.0 / OpenID Connect (TICKET-0105)

Run [requests/auth.http](../requests/auth.http) with the `task` and `kpi` private
environments generated by the development setup. Protocol endpoints use Spring
Security's OAuth/OIDC contracts and errors, not application DTO controllers.

| Endpoint | Contract |
| --- | --- |
| `GET /.well-known/openid-configuration` | Public OIDC metadata with configured issuer and endpoint URLs |
| `GET /.well-known/oauth-authorization-server` | Public OAuth metadata |
| `GET /oauth2/jwks` | Public RSA verification keys; never private parameters |
| `GET /login`, `POST /login` | Session login with `username` (canonicalized email), `password`, and form `_csrf` |
| `GET /oauth2/authorize` | `response_type=code`, registered client/redirect, scope, state, nonce, S256 code challenge; login required |
| `POST /oauth2/token` | Form-urlencoded authorization-code exchange with verifier, or refresh-token grant; HTTP Basic client authentication required |
| `GET /userinfo` | OIDC subject/email according to granted scopes, authenticated with a bearer access token |
| `POST /oauth2/revoke`, `/oauth2/introspect` | Framework protocol handlers with client authentication |

Both clients allow `openid profile email`. Task also allows `task.read task.write`;
KPI allows `kpi.read`. Registered callbacks are exactly
`http://127.0.0.1:8080/login/oauth2/code/task-management-ui` and
`http://127.0.0.1:8081/login/oauth2/code/kpi-ui`. No wildcard redirects or CORS origins
are configured. Client secrets are for server-side BFFs/HTTP tooling only.

Access tokens use RS256, configured `iss`/`kid`, UUID `sub`, expiration, authorized
`scope`, `roles` (for example EMPLOYEE), and `authorities` (ROLE_EMPLOYEE plus
permission names). Task scopes add audience `task-management`; `kpi.read` adds
`kpi-service`. An OIDC-only token has no resource audience and must not be accepted
by Task/KPI. ID tokens retain the client audience and requested nonce; email is
included only with the email scope, without an `email_verified` assertion.

Codes expire after two minutes and are single-use. Access JWTs live five minutes;
refresh tokens live eight hours and rotate on use. A rotated token or replayed code
returns `invalid_grant`; replaying a code also invalidates its stored authorization.
Missing/plain PKCE returns `invalid_request`. Bad client credentials return 401
`invalid_client`. An invalid redirect returns 400 without redirecting to that URL.
Disabled/missing users cannot exchange or refresh tokens. These are protocol
responses; login failure redirects to `/login?error` and missing login CSRF is 403.
